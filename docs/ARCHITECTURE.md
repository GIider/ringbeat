# Architecture

Vanilla ES modules, served as-is: no build step and no runtime dependencies. `index.html` loads `src/main.js`, which wires
the DOM to small, DOM-free logic modules that the node tests exercise directly. For how to run, test and debug, see
[DEVELOPMENT.md](DEVELOPMENT.md).

## Key decisions

- **One persistent phone.** The phone never moves. Menus, play, pause and results are all screens in the same LCD.
  - `body[data-mode]` is `menu`, `play` or `pause`, and is used for styling only.
  - The `#nowplaying` screen is the `#stage` canvas. It is drawn at one canvas pixel per LCD pixel
    (`renderer.setPixelScale(u)`), in two colours (LCD ink on the green backlight), and scaled up with
    `image-rendering: pixelated`.
  - Compact mode (window under 600 px wide or under 520 px tall) drops the phone body, so the LCD fills the viewport.
- **Crisp pixel text.** The LCD font size is 30 px on a wide LCD and 20 px otherwise. It is then snapped so that one font
  pixel is a whole number of device pixels (`u = round(fs / 10 × dpr) / dpr`, `--fs = 10u`). The canvas does not use
  `fillText`: `render.js` draws the same glyph table as sprites, so canvas and DOM text match pixel for pixel.
- **Soft keys.** Each screen declares `data-title`, `data-soft-left` and `data-soft-right`.
  - Right soft key (the C key) = `back()`.
  - Left soft key (the Menu key) = a per-state action (`softLeft`), by default "select the focused item".
  - With the phone body drawn, only the left label shows, centred. The bare LCD shows both labels.
  - The ▲▼ rocker and keypad 2/4/6/8/5 map to the same navigation as the arrow keys and the d-pad.
- **Focus navigation, not custom menus.** Every screen is ordinary focusable DOM. Keyboard arrows and the gamepad
  d-pad both go through `nav.js` (nearest control in that direction), which keeps touch, mouse, keyboard and pad
  consistent.
- **Selection by focus.** In the song list, focusing a row selects it, and confirming the selected row plays it.
  - Keyboard / pad confirm plays.
  - A mouse click only selects; a double-click plays. This way pointer users don't launch songs by accident.
  - On touch, tapping the already-selected row plays it, and swiping the list changes the category.
- **Audio clock only.** `AudioContext.currentTime` is the single time source for judging.
  - Key and pointer events are mapped onto it with `eventAudioTime`.
  - Pad edges carry `performance.now()`-domain timestamps (the pad's own timestamp when sane) and go through the
    same mapping.
  - Rendering reads the game state but never feeds judging. See [SPEC.md › Timing model](SPEC.md#timing-model).
- **Mods = chart transform + Game options.**
  - Speed and Mirror transform the generated chart before `Game.start`.
  - Judging and Sudden death are `Game.start` options (the hit windows belong to each Game instance).
  - Hidden is renderer-only.
  - Demo attaches `autoplay.js`.
  - The tutorial ignores mods.
- **Main menu.** The title leads to `menu`, a single screen showing one item at a time (3310 style). Every top-level
  screen's Back returns to it, on the item it was opened from; that item is remembered for the session, not saved.
  The icon frames advance from the frame loop (every ~300 ms) and are held still under reduced motion. The icon scale
  (2–4 LCD px per sprite px) follows the available space.
- **Ratings are measured offline.** Built-in song ratings come from bots playing the real `Game` (`npm run bench`).
  They ship as `difficulty.json` and are loaded after first paint, so startup never waits on them. See
  [SONGS.md › Difficulty ratings](SONGS.md#difficulty-ratings).
- **Testable logic.** Stores take an injectable storage object, and the logic modules don't touch the DOM. `main.js` is
  the only large DOM module.

## Persistence

Everything lives in `localStorage`. Every read is guarded and validated, so blocked or corrupted storage falls back to
defaults.

| Key | Module | Holds |
|---|---|---|
| `ringbeat.v1` | `settings.js` | Settings: voice, language, volume, scroll time, toggles, calibration, difficulty, list view, last song, tutorial progress, pad bindings, mods, read messages |
| `ringbeat.scores.v1` | `scores.js` | Highscores: top 5 runs and play count per song id × difficulty |
| `ringbeat.stats.v1` | `stats.js` | Lifetime stats |
| `ringbeat.songs.v1` | `mysongs.js` | My songs (up to 30 added by hand; a cloud merge may bring more) |
| `ringbeat.songs.gone.v1` | `mysongs.js` | Deleted songs' uids and when, so deletes reach other devices |
| `ringbeat.cloud.v1` | `cloud.js` | Online profile: token, profile, last sync, other devices' scores and stats, run outbox, reset marks, sync fingerprints, last world ranks |
| `ringbeat.boards.v1` | `cloud.js` | The leaderboard snapshot (`GET /boards`) and when it came, kept 15 minutes |
| `ringbeat.device.v1` | `cloud.js` | This device's random id |
| `ringbeat.api` | `main.js` | Developer override of the API address (see [CLOUD.md](CLOUD.md#local-development)) |
| `ringbeat.perf` | `main.js` | Profiler left on with F3 |

`ringbeat.v1` also holds `_t` (when each synced setting last changed) and `_fav` (favourite marks with times) for cloud
sync. Grade counts on the Stats screen are derived from the highscores, never stored twice. Custom songs' scores are keyed by
a hash of their RTTTL.
